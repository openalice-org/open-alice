# Contributing to OpenAlice

OpenAlice is an open-source map of research connections. Contributions to the
application, documentation, accessibility, and the quality of the map are
welcome. You can start with a question or a small correction; you do not need
to join the GitHub organization.

## Start a conversation

Use the [open-alice issue tracker](https://github.com/openalice-org/open-alice/issues)
for questions and proposals about the application, the data pipeline, or the
website. It is the shared public entry point for OpenAlice. Tell us which part
your issue concerns. For a bug, include what you expected, what happened, and
a link or screenshot when it helps. For a substantial change, discuss the
approach in an issue before doing the work.

The map's data is generated by the separate
[open-alice-data](https://github.com/openalice-org/open-alice-data) repository.
Its [methodology](https://github.com/openalice-org/open-alice-data/blob/main/docs/METHODOLOGY.md)
describes how the data is made and where it is uncertain. The
[website](https://github.com/openalice-org/openalice.org) has its own repository
too. Open a pull request in the repository you are changing; start a question
or proposal in the shared issue tracker.

## Propose a change

1. Fork the relevant repository and make a branch in your fork.
2. Keep the change focused. Explain the problem and your approach in the pull
   request. Link the issue if there is one.
3. For a visual change, include a screenshot. For a data or methods change,
   explain the source, the reasoning, and any limits you found.
4. Run the checks that apply to your change and say which ones you ran.

For this application, use Node.js 24 or later:

```bash
npm ci
npm run dev
```

Before opening a pull request that changes application code, run:

```bash
npm run lint
npm run build
```

The [README](README.md#run-locally) has more setup detail. The data pipeline
has different requirements; follow its own README when working there.

Maintainers review proposals in the public pull request. They may ask for a
smaller scope or a different approach before merging. Please keep credentials,
private files, and unpublished data out of issues and pull requests.
